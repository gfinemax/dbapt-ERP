# 9. 지출·정산 운영기준

이 장은 조합의 지출, 개인 선지출, 선지급, 신탁 집행과 월 마감을 같은 기준으로 처리하기 위한 사용자 안내다. 실제 거래일과 예산 귀속월을 보존하면서도 이미 마감하거나 보고한 회계자료를 임의로 덮어쓰지 않는 것이 핵심이다.

이 기준은 ERP 사용을 위한 내부 운영 권고안이다. 정식 시행 전에는 조합 규약, 총회·이사회 의결, 신탁계약, 세무상 지위와 적용 회계기준을 확인하고 필요한 경우 회계사 또는 변호사의 검토를 받는다. 금액별 승인한도와 담당자는 조합이 의결한 기준을 사용하며 임의의 기본값을 두지 않는다.

## 1. 모든 지출에 적용하는 원칙

1. 실제 거래 사실과 날짜를 임의로 바꾸지 않는다.
2. 실제 사용월의 예산과 실제 지급월의 현금 흐름을 분리한다.
3. 법인카드 승인내역, 영수증, 지출결의, 전표는 같은 지출의 관련 원본일 수 있으므로 단순 합산하지 않는다.
4. 마감된 자료는 삭제하거나 덮어쓰지 않고 조정 사유와 수정 버전을 추가한다.
5. 신청자, 승인자와 지급 실행자를 가능한 범위에서 분리하며 본인 신청을 본인이 최종 승인하지 않는다.
6. 신탁 승인, 조합 내부 승인, 실제 지급과 회계 전표는 서로 다른 단계로 기록한다.

## 2. 입력 전에 처리경로 결정하기

다음 순서로 판단한다.

1. **누가 먼저 돈을 냈는가**를 확인한다.
2. **법인카드·조합계좌·개인카드·개인 현금·선지급금** 중 실제 결제수단을 확인한다.
3. **승인 예산 안의 통상 지출인지, 예산 외 또는 계약·사업비인지** 확인한다.
4. **신탁사 집행요청이 필요한 사업비인지** 확인한다.
5. **증빙, 실제 사용일과 거래처를 확인할 수 있는지** 확인한다.
6. 정상 경로를 선택하기 어려우면 임의 등록하지 않고 회계·예산 담당자에게 확인을 요청한다.

| 상황 | 기본 처리경로 | 주의사항 |
| --- | --- | --- |
| 법인카드·법인 온라인카드 | 법인카드 간편처리 | 카드 승인내역과 증빙을 연결한다. |
| 조합계좌 직접 이체 | 직접지출 또는 지출결의 | 실제 출금거래와 승인 문서를 연결한다. |
| 개인카드·개인계좌·개인 현금 | 개인 선지출 정산 | 개인에게 반환할 금액과 실제 지급을 구분한다. |
| 조합이 먼저 지급한 금액 | 선지급 사용정산 | 사용액, 잔액과 반납액을 모두 정산한다. |
| 월 운영비 범위의 소액 집행 | 운영비 사용정산 | 월별 사용대장과 증빙으로 정리한다. |
| 토지비·용역비·공사비 등 사업비 | 지출결의 후 신탁 집행요청 | 신탁 승인만으로 내부 승인·지급·전표가 완료되지 않는다. |
| 안전사고 등 불가피한 긴급지출 | 긴급지출 사후승인 | 최소금액만 집행하고 다음 영업일까지 보고한다. |
| 자동이체·정기구독 | 정기지출 간편처리 | 계약·해지 조건과 매월 실제 출금을 확인한다. |

## 3. 날짜와 월을 구분하는 방법

| 항목 | 의미 | 변경 원칙 |
| --- | --- | --- |
| 실제 사용일 | 재화·서비스를 사용하거나 실제 결제한 날 | 증빙에 따라 기록하고 임의 변경하지 않는다. |
| 예산 귀속월 | 실제 사용일이 속한 예산월 | 현재 월에 맞추기 위해 옮기지 않는다. |
| 신청·등록일 | ERP에 제출한 실제 시점 | 과거 날짜로 소급하지 않는다. |
| 승인일 | 승인권자가 실제 처리한 시점 | 시스템 이력으로 보존한다. |
| 실제 지급일 | 조합계좌에서 출금된 날 | 연결한 은행거래의 일시를 사용한다. |
| 회계 반영일 | 전표를 회계장부에 반영한 날 | 마감 상태와 회계정책에 따라 결정한다. |

예를 들어 1월에 개인카드로 사용하고 7월에 환급했다면 실제 사용일과 예산 귀속월은 1월이고, 신청일·승인일·실제 지급일은 각각 7월의 실제 처리일이다.

## 4. 예산 처리기준

- 모든 지출은 원칙적으로 승인된 예산항목과 실제 사용월에 반영한다.
- 예산이 부족하면 다른 항목이나 월로 임의 이동하지 않고 예산 초과 승인을 받는다.
- 여러 달에 걸친 계약은 계약기간과 합리적인 산정근거에 따라 월별로 배분할 수 있다.
- 사용월 또는 예산항목을 확인할 수 없는 원본은 `귀속 확인 필요`로 보류한다.
- 개인 선지출은 별도 예산이 아니라 결제수단의 차이이므로 같은 예산 통제를 적용한다.
- 마감월의 예산을 조정하면 기존 보고서를 보존하고 조정 사유가 포함된 새 버전을 생성한다.

## 5. 신청기한과 지연 처리

다음 기준을 권장한다. 조합이 다른 기한을 의결했다면 의결된 기준을 우선한다.

| 신청 시점 | 처리상태 | 필요한 조치 |
| --- | --- | --- |
| 익월 마감일 또는 사용 후 30일 이내 | 정상 접수 | 일반 증빙·예산 심사 |
| 31일부터 60일까지 | 지연 접수 | 지연 사유 입력 및 담당자 확인 |
| 61일부터 180일까지 | 장기 지연 | 지연 승인과 상위 승인자의 추가 승인 |
| 180일 초과 | 원칙적 거절 | 객관적 증빙과 불가피한 사유가 있는 경우에만 예외심사 |
| 회계연도 경과 | 일반 접수 불가 | 별도 회계검토와 정정·당기조정 판단 |

180일을 넘은 신청은 업무 관련성, 결제 사실, 중복 여부, 당시 승인 또는 담당자 확인, 지연 사유, 원래 사용월의 예산과 마감 영향을 모두 확인한다. 기간이 지났다는 사유만으로 기존 기록을 삭제하지 않으며, 지급거절 결정과 사유도 보존한다.

## 6. 마감되거나 보고된 기간의 지출

실제 사용일은 사실대로 보존하되 과거 장부를 항상 다시 열지는 않는다.

| 상태 | 처리방법 |
| --- | --- |
| 해당 월 미마감 | 실제 사용월에 정상 반영한다. |
| 월 마감 완료·연간 결산 전 | 사용월 예산에 과거월 조정을 반영하고 월 보고서 수정 버전을 만든다. |
| 연간 보고 전의 경미한 누락 | 조합 회계정책에 따라 현재 기간에 과거월 조정으로 기록하고 사용월 예산 조정명세를 남긴다. |
| 연간 보고 완료·중요하지 않은 오류 | 발견한 기간에 전기분 조정으로 처리하고 조정명세 또는 주석을 남긴다. |
| 연간 보고 완료·중요한 오류 | 회계전문가 검토 후 비교정보 재작성, 정정보고 또는 재보고 여부를 결정한다. |
| 신탁·특수관계인·부정 의심 거래 | 금액과 관계없이 중요사항으로 별도 심사한다. |

중요성은 금액만으로 판단하지 않는다. 예산 초과 여부, 조합원 보고 내용의 변경, 신탁자금, 특수관계인 거래, 승인 우회, 반복 누락과 부정 가능성을 함께 검토한다. 원보고서를 직접 수정하거나 삭제하지 않고 변경 전·후 금액, 사유, 처리자, 승인자, 처리일과 보고서 버전을 남긴다.

### 마감 후 개인 선지출 예시

1. 1월 15일 개인카드 사용 사실과 1월 예산 귀속을 기록한다.
2. 7월 신청일과 180일 초과 여부를 그대로 계산한다.
3. 증빙, 업무 관련성, 중복 지급과 예산 영향을 검토한다.
4. 장기 지연 승인과 필요한 경우 예산 초과·마감월 조정 승인을 받는다.
5. 중요성 검토에 따라 과거월 조정 또는 정정보고 방식을 결정한다.
6. 7월 실제 출금거래를 개인 환급과 연결한다.
7. 목록에는 `1월 사용 · 7월 신청·지급 · 과거월 조정`으로 표시한다.

## 7. 증빙과 보완

우선 확인할 증빙은 세금계산서·계산서, 카드매출전표, 현금영수증, 계좌이체 내역, 거래명세서, 계약서, 견적서와 납품확인서다. 조합의 세무상 지위에 따라 적격증빙 요건이 달라질 수 있으므로 회계담당자가 적용 기준을 확인한다.

영수증이 없다는 사실만으로 즉시 거절하지 않는다. 영수증 미첨부 사유, 카드·계좌 내역, 주문내역, 물품 사진, 거래처 확인과 담당자 사실확인 등 대체증빙을 제출하고 신청자와 다른 승인자가 검토한다. 거래 사실, 금액 또는 업무 관련성을 확인할 수 없으면 지급하지 않는다.

OCR 결과는 입력 초안이다. 원본과 대조해 실제 사용일, 거래처, 금액, 사용내용과 예산항목을 수정할 수 있으며, 사용자가 직접 고친 값을 자동 추천이 다시 덮어쓰지 않는다.

## 8. 개인 선지출

- 조합 결제가 가능한 경우에는 법인카드나 조합계좌를 우선 사용한다.
- 신청자는 실제 결제자와 환급받을 사람을 확인할 수 있는 자료를 제출한다.
- 개인카드 사용분도 실제 사용월의 예산과 동일한 한도 통제를 받는다.
- 본인 신청은 본인이 최종 승인하거나 지급 완료 처리하지 않는다.
- 지급 시 신청자, 환급계좌와 실제 출금거래를 확인한다.
- 이미 법인카드·계좌이체·다른 정산으로 처리한 금액은 중복 지급하지 않는다.

## 9. 선지급

- 지급 전에 목적, 지급액, 사용기한, 정산기한과 책임자를 정한다.
- 목적이 끝나거나 사용기한이 지나면 사용액과 증빙을 제출한다.
- 남은 금액은 조합계좌에 반환하고 실제 입금거래와 연결한다.
- 승인액을 넘은 사용분은 자동 정산하지 않고 추가 승인을 받는다.
- 미정산 선지급금이 있으면 후속 선지급을 제한할 수 있다.

## 10. 신탁자금

- 월 운영비는 신탁사에서 수령한 범위 안에서 조합이 집행하고 월별 사용대장과 증빙으로 정산한다.
- 월 운영비 범위의 통상 소액지출을 모두 개별 신탁 집행요청으로 만들지 않는다. 다만 신탁계약에서 개별 보고를 요구하면 그 계약을 우선한다.
- 토지비, 용역비, 공사비 등 사업비는 내부 지출결의 승인 후 신탁 집행요청을 진행한다.
- 운영비와 사업비를 임의로 전용하지 않는다.
- 신탁사 승인, 조합 내부 승인, 실제 지급과 회계 전표를 각각 기록한다.

## 11. 긴급지출

안전사고, 누수, 시스템 장애 등 사전승인이 현실적으로 불가능한 경우에는 필요한 최소금액만 집행한다. 긴급 사유와 현장자료를 남기고 다음 영업일까지 보고하며 정해진 기간 안에 사후승인을 받는다. 단순한 일정 누락이나 준비 부족은 긴급사유로 인정하지 않는다.

## 12. 지급거절과 보완

다음 사유가 있으면 지급을 거절한다.

- 조합 업무와 무관한 개인 사용
- 허위·변조 증빙
- 이미 지급했거나 다른 원본으로 처리한 중복 신청
- 거래 사실, 금액 또는 실제 결제자를 확인할 수 없는 신청
- 승인한도를 피하기 위한 분할 등록
- 사전승인이 필수인 사업비의 무단 집행
- 이해충돌 또는 특수관계인 거래의 은폐
- 취소·환불된 거래의 원금 정산
- 보완 요청에 정당한 사유 없이 응하지 않은 신청

단순 오기나 형식상 누락은 즉시 거절하지 않고 보완 기회를 준다. 반려·거절 사유와 제출된 원본은 감사 이력으로 보존한다.

## 13. 취소·환불·정정

- 원거래와 취소·환불 거래를 연결한다.
- 카드 취소는 원래 사용월의 예산을 복원한다.
- 지급 후 환불은 조합계좌의 실제 입금을 확인한 뒤 예산과 전표를 정정한다.
- 일부 환불은 원금액을 덮어쓰지 않고 원거래, 환불액과 순지출액을 함께 보존한다.
- 잘못 연결한 지급은 연결을 취소하되 은행 송금 자체가 취소된 것으로 처리하지 않는다.

## 14. 월 마감과 권한

월 상태는 `접수 중`, `보완 중`, `마감`으로 구분한다. 마감 후에는 일반 수정 대신 승인된 조정을 사용한다.

| 역할 | 주요 책임 |
| --- | --- |
| 신청자 | 실제 사용내역과 증빙 제출 |
| 증빙 검토자 | 업무 관련성, 원본과 대체증빙 확인 |
| 예산 확인자 | 예산항목·귀속월·한도 확인 |
| 승인자 | 정상·지연·예외·초과 승인 |
| 지급 담당자 | 수취인·계좌·실제 출금 확인 |
| 회계 담당자 | 전표 확정, 과거월 조정과 보고 영향 검토 |
| 마감 담당자 | 미처리 원본 점검, 마감 및 수정 버전 관리 |

가능하면 신청자, 최종 승인자와 지급 담당자를 분리한다. 시스템 권한이 있더라도 이해충돌이 있으면 다른 승인자가 처리한다.

## 15. ERP 처리상태

일반적인 처리 흐름은 다음과 같다.

`작성 중 → 증빙 확인 → 예산 확인 → 승인대기 → 승인완료 → 지급대기 → 실제 지급 연결 → 전표 확정 → 월 마감`

다음 예외상태는 일반 진행상태와 별도로 표시한다.

- 지연 사유 필요
- 장기 지연 승인 필요
- 예산 초과 승인 필요
- 마감월 조정 필요
- 중요성 검토 필요
- 신탁 승인 필요
- 증빙 보완 필요
- 중복 의심
- 지급거절

전체 지출 목록은 실제 거래일을 기본 기준으로 정렬한다. 등록일, 승인일과 지급일은 상세에서 함께 확인하고, 업무 담당자는 `처리 필요 우선`, `지연일수 높은순`, `업무흐름 미연결` 필터를 사용한다.

## 16. 제출·승인 체크리스트

### 신청자

- 실제 사용일과 결제수단이 맞는가
- 거래처, 사용내용과 금액이 원본과 일치하는가
- 올바른 예산항목을 선택했는가
- 증빙 또는 대체증빙과 사유를 첨부했는가
- 기존 카드·계좌·정산 원본과 중복되지 않는가
- 지연된 경우 지연 사유를 입력했는가

### 검토·승인자

- 조합 업무와 관련된 지출인가
- 실제 결제자와 지급받을 사람이 맞는가
- 사전승인 또는 예외승인 근거가 있는가
- 사용월 예산과 초과 여부를 확인했는가
- 마감월·전년도·신탁·특수관계인 거래인가
- 기존 보고서 정정 또는 조정명세가 필요한가

### 지급·회계 담당자

- 승인금액과 실제 출금액이 같은가
- 수취인과 계좌가 맞는가
- 동일 출금거래가 다른 지급에 사용되지 않았는가
- 예산 사용액을 지급 시 다시 차감하지 않았는가
- 회계 반영일과 실제 지급일을 구분했는가
- 마감 후 조정 사유와 보고서 버전을 남겼는가

## 17. 권장 초기값과 설정모드

ERP에는 아래 값을 `추천안·미확정` 상태로 제공한다. 추천값을 불러오는 것만으로는 운영규정이나 진행 중인 신청에 효력이 생기지 않는다. 조합의 계약, 예산규모와 의결사항에 맞게 관리자가 검토·수정하고 다른 승인자가 승인한 뒤 시행일에 활성화한다.

### 권장 초기값

| 설정 영역 | 권장값 | 처리 원칙 |
| --- | --- | --- |
| 신청기한 | 30일 이내 정상, 31~60일 지연, 61~180일 장기 지연, 180일 초과 원칙적 거절 | 객관적 증빙과 불가피한 사유가 있으면 예외심사하며, 회계연도 경과 건은 일반 접수를 막고 별도 회계검토로 보낸다. |
| 금액별 승인 | 예산 내 50만원 이하 간소 승인, 50만원 초과~300만원 일반 승인, 300만원 초과 상위·복수 승인 | 예산 외 지출, 신탁 사업비, 특수관계인 거래는 금액과 관계없이 별도 승인한다. 금액을 나누어 한도를 피하지 않는다. |
| 회계 중요성 | 100만원 이상 또는 해당 월 예산의 1% 이상이면 중요성 검토 | 아래 정성 기준 중 하나라도 해당하면 금액과 관계없이 중요성 검토를 한다. |
| 과거연도 처리 | 일반 접수 차단 후 별도 회계검토 | `회계 확인 → 상위 예외승인 → 외부 회계전문가 검토 → 필요한 경우 이사회·총회 보고 또는 의결 → 지급` 순서로 처리한다. |

금액 기준은 모든 지출의 지급을 자동 허용하는 기준이 아니다. 계약·법령·정관·총회 또는 이사회 의결에서 더 엄격한 한도를 정했다면 그 기준을 우선한다.

### 중요성 검토 조건

다음 중 하나라도 해당하면 금액기준 미만이어도 `중요성 검토 필요`로 표시한다.

- 해당 월 예산을 초과하거나 예산항목의 변경·전용이 필요한 경우
- 신탁 사업비 또는 특수관계인과의 거래인 경우
- 중복, 허위, 분할등록, 승인 우회 등 부정 가능성이 있는 경우
- 이미 배포한 월·연간 회계보고의 수치나 결론을 바꾸는 경우
- 외부감사, 세무신고 또는 조합원 보고에 영향을 줄 수 있는 경우

### 설정 화면 구성

`회계/자금 → 지출·신탁 설정 → 운영 기준`에서 다음 탭을 제공한다.

1. `처리기한`: 정상·지연·장기 지연·원칙적 거절의 경계일과 예외 허용 여부
2. `금액별 승인`: 금액 구간, 예산 내·외, 필요한 승인 단계와 승인자 역할
3. `회계 중요성`: 금액, 월 예산 비율과 정성 조건
4. `과거연도 처리`: 접수 제한, 예외 승인경로, 전문가 검토와 보고 기준
5. `정책 변경이력`: 버전, 변경 전·후 값, 사유, 작성자·승인자와 시행기간

각 설정에는 현재값, `추천값 불러오기`, 변경값, 시행일, 변경 사유, 승인자와 상태를 표시한다. 상태는 `초안 → 승인대기 → 활성 → 종료` 순서로 관리하고, 가능하면 설정 작성자와 활성 승인자를 분리한다.

### 변경·활성화 절차

1. 관리자가 추천값을 불러오거나 현재값을 복사해 초안을 만든다.
2. 조합의 의결사항과 계약조건에 맞게 값을 수정하고 변경 사유와 시행일을 입력한다.
3. `영향 미리보기`에서 새 기준에 해당하는 미처리 신청 건수와 상태 변화 예상치를 확인한다.
4. 다른 승인자가 변경 전·후 값을 비교해 승인한다.
5. 시행일이 되면 새 신청부터 새 정책 버전을 적용한다.

신청을 제출할 때 적용한 정책 버전을 신청 기록에 고정한다. 정책을 바꿔도 기존 신청, 지급완료 건과 마감월을 조용히 소급 변경하지 않는다. 진행 중인 신청에 새 정책을 적용하려면 영향대상과 변경 결과를 먼저 보여주고 별도 승인을 받아야 한다. 변경한 정책은 삭제하지 않고 종료 처리하여 유효기간과 감사 이력을 보존한다.

## 18. 규정 시행과 변경

새 규정은 시행일과 경과조치를 함께 의결한다. 시행 전에 발생한 미정산 건에는 일정한 정리기간을 부여하고 그 이후부터 새 기한을 적용한다. 승인한도, 제출기한, 역할과 예외 기준을 바꾸면 변경일, 의결 근거와 적용 대상을 기록하고 이미 마감한 월에 임의로 소급하지 않는다.

주택조합은 거래 장부를 월별로 작성하고 증빙서류와 함께 보관해야 한다. ERP의 원본·변경·승인·지급·마감 이력은 이 의무를 지원하기 위한 기록이며, 원본 삭제나 이력 없는 수정을 허용하지 않는다.
