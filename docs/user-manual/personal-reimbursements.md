# 개인 지출 정산·월 마감

진입: 회계/자금 → 전표·증빙관리 → **개인 지출 정산·월 마감** (`/finance/reimbursements`). 결재 설정에서도 이동할 수 있다.

## 최초 설정

현재 ERP의 공통 헤더에 표시되는 ‘관리자’는 인증된 사용자 계정이 아니다. 이 기능은 Supabase Auth로 본인을 확인하고 별도의 조합별 권한을 검사한다. 계정을 임의로 만들거나 기존 이름을 계정에 자동 연결하지 않는다.

1. 운영자가 Supabase Auth에 최초 관리자 계정을 등록한다. 이메일을 자동 발송할 필요는 없다.
2. 해당 계정 UUID와 실제 조합 UUID를 `finance.reimbursement_members`에 등록하고 `ADMIN` 권한을 부여한다. 최초 등록은 서버 운영 권한으로만 수행한다.
3. 관리자가 로그인하여 운영 기준에서 **다음 달 제출 마감일, 보완 마감일, 장기 지연 일수**를 저장한다. 임의의 날짜 기본값은 없다. 마감일은 매월 존재하는 1~28일을 지원한다.
4. 담당자 계정과 역할을 등록한다. 본인 신청은 관리자도 본인이 승인할 수 없으므로 별도의 승인자가 필요하다. 초기 비밀번호는 12자 이상이며, 담당자는 로그인 후 비밀번호를 변경한다.
5. 해당 사용월을 선택하고 예산·마감 보고서 탭에서 접수월을 개설한다. 개설 시점의 기한이 보존되며, 이후 설정 변경은 기존 월에 소급되지 않는다.

권한: 신청자는 본인 신청만 열람한다. `APPROVE`는 정산·지연 심사, `SENIOR`는 장기 지연·예산 초과 승인, `CLOSE`는 월 마감·마감 후 예산 반영·승인 취소, `PAY`는 실제 지급 연결과 오연결 취소를 담당한다. `ADMIN`은 이 권한들과 담당자 관리를 수행한다. 비활성화는 다음 요청부터 적용된다. 로그인은 접근 토큰 유효기간 동안 유지되며 만료 시 재로그인한다.

## 정상 신청과 지연 신청

- 신청자는 실제 사용일, 사용처, 금액, 업무 목적, 예산항목과 증빙을 제출한다. 예산 귀속월은 사용일에서 정해진다.
- 증빙은 실제 PDF/PNG/JPEG/WebP 파일 하나(3MB 이하)로 보관한다. 영수증과 개인 결제 증빙을 하나의 PDF로 합쳐 제출할 수 있다. 비공개 저장소에 보관하며, 권한 확인 후 60초 유효한 열람 링크를 발급한다.
- 제출기한을 넘기거나 마감된 월에 제출하면 지연 사유와 예외 승인이 필요하다. 보완 기간은 신규 지연 신청을 정상 신청으로 바꾸는 유예가 아니다.
- 장기 지연 기준을 넘기면 추가 승인이 필요하다. 예산 부족은 별도의 예산 초과 승인으로 처리하며, 지연 승인만으로 한도 초과가 허용되지 않는다.
- 업무 담당자는 증빙의 업무 관련성, 실제 결제자와 반환받을 사람, 중복 정산 여부 및 필요한 지출 승인을 확인한다.
- 반려된 신청은 증빙·사유를 보완해 새로 신청한다. 기존 반려 기록은 남는다.

## 마감 후 3월 사용분을 정산하는 예

1. 3월 마감 보고서 버전 1을 보관한다.
2. 뒤늦게 신청된 3월 사용분을 지연·장기 지연 기준에 따라 승인한다.
3. 마감 권한자가 예산 반영 승인과 사유를 남기면 3월 개인 정산 승인액에 반영하고 버전 2를 자동 생성한다. 3월 전체를 편집 가능하게 열지 않는다.
4. 기존 보고서와 수정본을 모두 열람·인쇄할 수 있다. 수정본을 기존 보고 대상에게 전달하는 것은 담당자의 업무이며 시스템이 자동 발송하지 않는다.
5. 실제 6월 출금거래를 선택하면 지급일은 해당 거래의 일시로 기록된다. 정산 승인일이나 등록일을 과거로 바꾸지 않는다. 지급 연결은 실제 송금을 실행하지 않는다.

## 예산과 지급의 구분

월 현황은 간편지출, 개인 정산 승인액과 기안의 활성 집행 예약액을 표시한다. 기존 회계장부의 모든 지출을 월별 재분류한 보고서가 아니다. 정식 결의서·회계전표의 과거 날짜나 잔액을 이 기능이 변경하지 않는다. 기존 연간 집행 입력값에는 개인 정산 자동 합산액을 다시 입력하지 않는다.

기존 개인 간편지출은 담당자가 원본을 연결한다. 날짜·금액·예산항목을 대조하고 승인 시 원본을 전환 상태로 바꿔 중복 집계하지 않는다. 운영 기준 설정 후 신규 개인 간편지출은 이 신청 흐름으로 처리한다. 기존 원본을 임의로 삭제하지 않는다.

실제 지급 연결은 동일 조합·동일 금액·사용일 이후의 출금거래만 가능하다. 다른 정산·결의서·간편지출에 이미 사용된 거래는 차단된다. 분할지급과 여러 신청의 합산 이체 연결은 현재 지원하지 않으며, 각각의 동일 금액 출금거래를 연결한다.

지급 전 승인 취소는 예산 사용액을 복원하고 마감된 월이면 수정 보고서를 추가한다. 지급 후에는 먼저 잘못된 지급 연결을 취소해야 한다. 이는 은행 송금 취소나 환급 처리가 아니다. 모든 처리와 이전·이후 값은 감사 기록으로 보관한다.

## 범위와 검증

첫 적용 범위는 같은 회계연도 개인 선지출이다. 전년도 사용분은 별도 회계 검토 대상으로 차단한다. 증빙이 없는 신청은 지원하지 않는다. 정산 목록은 선택한 사용월 기준이며, 최근 처리 이력은 100건, 출금 연결 후보와 기존 선지출 후보는 최근 200건이다. 예산 합계는 DB 집계로 계산하므로 이 후보 표시 개수에 의해 줄어들지 않는다.

`supabase/tests/personal_reimbursement.sql`은 반드시 `BEGIN`/`ROLLBACK` 안에서 실행한다. 테스트는 임시 조합·사용자·증빙 메타데이터로 마감, 예외 승인, 실제 지급일, 취소 복원, 원본 연결, 예산 초과 및 권한 차단을 검사한다. 테스트 자료는 운영 기록으로 남기지 않는다.
