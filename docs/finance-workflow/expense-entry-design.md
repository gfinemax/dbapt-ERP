# 4c: 결의 작성 진입과 서버 저장 결과 보존

구현 전 조사: 공통 지출관리의 사전/사후 작성과 원본 상세 링크가 모두 기존 목록으로 이동한다. 기존 결의 화면은 서버 빈 목록을 공용 localStorage로 대체하고 저장 실패도 로컬 성공으로 취급한다. 이는 권한 거절이나 삭제 후 과거 자료를 다시 보여줄 수 있다.

## 재사용과 신규 작업

- 기존 결의 작성기, 저장 action, 원본 ID, 증빙, 결재 및 금액 산식은 재사용한다.
- 신규: 허용된 작성 진입값과 원본 ID 전달, 서버 조회 결과 우선, 실패 시 입력 유지 및 중복 클릭 방지.
- 별도 후속: 기존 action 전체 Auth UUID·조직 검증과 표시이름 결재선의 명시적 UUID 연결. 이번 UI 변경을 서버 권한 개선 완료로 간주하지 않는다.
- 회계 확정 권한·수납 원장 정책은 미확정이며 기존 실행 제한을 유지한다.

## 원본 연결 및 URL 대응

|기존 진입|새 진입|처리|
|---|---|---|
|사전 결의 → 결의 목록|/finance/expense-resolutions?start=advance|기존 작성기를 사전결의로 연다|
|사후 결의 → 결의 목록|/finance/expense-resolutions?start=reimbursement|기존 작성기를 사후정산으로 연다|
|원본 결의 → 결의 목록|/finance/expense-resolutions?resolutionId=원본ID|조회된 목록에서 정확한 ID의 상세를 연다|
|기존 URL, 잘못된 start|기존 목록|신규 작성이나 저장을 실행하지 않는다|

상세 ID가 있으면 작성값보다 우선한다. ID를 찾을 수 없으면 안내하며 다른 원본으로 대체하지 않는다. URL은 조회/작성 초기값일 뿐 승인·지급·권한 근거가 아니다.

## 상태 전환 및 금액 예제

|사건|화면|서버 자료|
|---|---|---|
|작성 링크 이동|입력 중|변경 없음|
|저장 요청 중|추가 저장 요청 차단|기존 저장 action만 호출|
|저장 성공|서버 반환 원본으로 목록 반영|기존 저장 계약 유지|
|저장 실패|입력과 오류 유지, 재시도 가능|성공으로 표시하거나 로컬 목록에 추가하지 않음|
|서버 재조회 빈 목록|0건|브라우저 과거 목록 복원 안 함|

예: 3월 사용 10,000원을 6월 신청하는 사후 결의를 열어도 금액·실제 사용일·지급일을 URL로 생성하지 않는다. 입력 전 금액은 기존 빈 작성기의 0원이며 실제 사용일은 빈칸이다. 사후정산 선택 자체는 10,000원 지급 사실이 아니다.

## 완료 기준

진입값 제한, 정확한 ID 상세/없는 ID, 원본 불변, 서버 빈 목록/실패에서 캐시 배제, 저장 실패 후 입력 유지·재시도, 동시 클릭 한 번, 성공 후 서버 원본 재조회 테스트. 기존 작성·수정 회귀와 빌드 확인. 운영 DB 변경 없음. DB 권한·원자적 승인·서버 간 동시 저장 전체 검증은 별도 단계이다.

## 구현 및 검증 결과

2026-09-08: 작성 진입·상세 ID 연결과 서버 저장 결과 보존을 구현했다. 서버 조회 결과가 제공되는 화면은 공용 localStorage를 읽거나 쓰지 않는다. 기존 브라우저 자료는 삭제하지 않으며 서버 자료가 없는 독립 작성기에서만 기존 로컬 저장 동작을 유지한다. 저장 오류는 입력을 유지하고 성공 시각도 표시하지 않는다. 동일 작성기의 처리 중 저장 클릭은 한 번만 호출한다.

관련 5개 테스트 파일 54개 통과: route 진입값, 일반 신청자에게 담당자 전용 작성 링크 미노출, 권한 거절을 모사한 저장 실패, 서버 빈 목록·재조회, 저장 응답 후 정확한 ID 상세, 재시도 ID 유지, 중복 클릭, 기존 작성·수정·증빙 회귀. 저장/재조회 검증은 UI 테스트의 서버 응답 대역으로 수행했으며 이번 단계에서 실제 운영 저장이나 새로운 DB 권한 검증을 수행한 것은 아니다. 실제 브라우저 재검증도 이번 단계에는 포함하지 않았다.

프로덕션 빌드 통과. ESLint 오류 0건, 기존 미사용 변수 경고 1건. 전체 TypeScript 검사에는 기존 테스트의 오류 13건이 남아 있다. 이전 14건 중 기존 `/finance/exp`에서 전달하는 searchParams 인자 오류가 이번 route 시그니처 보완으로 해소되었고 신규 오류는 없다.

운영 마이그레이션/배포 확인은 미실시. 기존 결의 action의 서버 Auth UUID·조직·결재선 연결 및 원자적 저장 개선은 후속 미완료 단계다.
