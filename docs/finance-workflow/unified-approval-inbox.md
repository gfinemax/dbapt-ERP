# 기안·지출 통합 결재함

- 등록·보완: `/finance/expenses` → `/finance/expenses/small`.
- 확인·확정: `/approval/inbox`의 전체 확인대기 또는 소액지출 확인.
- 지출결의 승인: `/approval/inbox?type=expense`. 회계/자금의 지출 승인함도 이 화면을 연다.
- 기존 `/approval/small-expense?month=...`는 사용월을 유지해 확인 화면으로 이동한다. `/finance/approval-inbox`는 지출결의 보기로 이동한다.
- 기안 목록은 원본 작성·진행·이력 조회 화면으로 유지한다.

통합 목록은 기존 문서의 계정 ID 기반 승인 권한을 재사용한다. 일반 기안/지출결의 읽기 권한이 없는 소액 담당자에게 일반 문서를 제공하지 않는다. 소액 확인대기는 지정 조합장에게만 제공하며 본인 등록·사용, 기존 일괄결의 연결, 삭제 내역을 제외한다. 사용월 전체를 페이지 단위로 읽어 지난달 대기를 빠뜨리지 않는다. 일부 조회가 실패하면 해당 오류와 조회 가능한 내역을 함께 표시한다.

소액 등록/확인 화면은 같은 원본과 기존 RPC를 사용한다. 등록 화면에 확정 버튼을, 확인 화면에 신규 등록 폼을 제공하지 않는다. 기존 등록·보완·취소·확정의 권한/버전 검증을 유지한다. 확정 후 간편지출 예산 원본은 기존 방식으로 한 번 생성하고, 별도 결의서를 생성하지 않는다. 일반 간편지출의 결의 생략 정책과 정식 결의 경로도 유지한다.

## 2026-09-19 검증과 운영 선행 변경

운영에서 `20260906234558_small_expense_chair_confirmation`만 누락되어 기존 소액 화면도 DB 업데이트 필요 상태였다. 당시 소액 원본 0건, 간편지출 6건, Storage 객체 43건이었다.

운영 DB 전체 백업: `.tmp-repos/finance-operational-db-backup-2026-09-18T23-49-35-625Z-58478f43` (Git 제외). 완료 manifest와 백업 시각을 확인한 후 `scripts/apply-small-expense-confirmation.mjs`로 누락된 기존 migration 하나만 적용했다. 기존 이력의 버전을 바꾸지 않고 원래 버전 `20260906234558`을 기록했다. 기안/지출 원본 및 증빙 파일은 삭제하지 않았다.

적용 전 기존 SQL 회귀를 BEGIN/ROLLBACK으로 실행해 등록·보완·확정, 본인 확인 차단, 계정/조직 권한, 증빙/거래 연결, 중복 처리, 예산 1회 반영, 마감 제한을 검증했다. 적용 트랜잭션에서 기존 간편지출·결의·Storage 객체의 지문이 유지되는지 검사했다. 적용 후 REST에서 담당자/원본/감사 테이블을 다시 조회했다. 실제 담당자는 자동 지정하지 않았으며 사용자 계정 확인 후 설정해야 한다.

UI/권한/회귀 테스트 20파일 95건과 프로덕션 빌드를 통과했다. 날짜가 흐르면서 180일 제한에 걸리던 기존 사후결의 테스트는 테스트 시계를 고정했다. 전체 `tsc --noEmit`은 기존 금융 테스트 타입 오류가 있어 프로덕션 빌드 결과와 구분한다.

보안 점검에서 새 소액 테이블은 RLS 및 서비스 계정 전용 접근을 유지한다. 정책 없음 정보는 브라우저 직접 접근을 차단하는 현재 설계에 해당한다. 별개 기존 경고: [기존 함수 search_path](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable), [유출 비밀번호 보호](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). 이번 메뉴 통합에서 조직 Auth 설정을 변경하지 않았다.
