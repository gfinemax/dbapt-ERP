# 4b 업무현황·메뉴·기존 경로 연결

상단 업무 분류를 유지하고 그룹·순서를 고정한다. 기존 상세 라벨은 새 라벨에 대응해 현재 위치를 보존하며 모바일에서도 같은 메뉴를 사용한다. 기존 원본 작성·증빙·출력 URL은 제거하지 않는다.

## 지급 URL 전환

- `/finance/payment-waiting` → `/finance/payments?tab=UNPAID`
- `/finance/payment-completed` → `/finance/payments?tab=PAID`

기존 tab만 목적 상태로 교체하고 q·from·반복 query 등 나머지 문맥은 보존한다. 새 지급 화면은 미연결 기존 기록을 별도 목록으로 표시한다. 원본 금액을 실제 지급액으로 대체하거나 이전 지급완료를 지급대기로 바꾸지 않는다. 통합 연결된 원본은 이전 목록에서 제외한다. 미연결 과거 기록은 새로운 지급 가능액을 만들지 않는다.

## 업무현황과 실패 처리

검증된 사용자 UUID로 본인 순서의 기안을 조회한다. 별도의 승인대기 지출은 조직 상태 목록이며 본인 결재 건수로 표현하지 않는다. 신탁 준비는 최신 원본·내부 승인·유효 계약·요청 잔액만 확인하고 서류/제출조건 확인을 별도로 안내한다. 지급 가능은 서버 지급 조건 검증 결과만 사용한다.

원천 조회 하나가 실패하면 해당 카드에 조회 실패를 표시하고 독립 자료를 유지한다. 같은 거래의 여러 처리 업무를 금액 실적으로 합산하지 않는다. 카드 선택·검색·초기화·새로고침과 query 상태를 유지한다. 지급/은행 상세 링크는 기존 검색·목록 이동이며 해당 원본의 직접 실행을 자동 수행하지 않는다.

## 미완료 및 정책 의존 범위

전체 원본 작성기의 통합 편집·승인, 기존 label 기반 승인자와 서버 Auth UUID의 연결, 카드 원본 통합 상세, 실제 수납/환급 원장 bridge, 선지급 확정 및 회계 확정·정정, 전사 월 잠금은 후속 범위다. 회계 확정 권한 및 수납 원본 시스템을 사용자에게 확인 요청했다. 정책 미확정 실행은 활성화하지 않는다.

메뉴 연결 완료는 위 미완료 업무의 운영 실행 완료를 의미하지 않는다. 운영 migration/배포는 별도 적용 상태 보고를 따른다.
