## 1단계 구현

- 기존 결의/간편지출/개인 정산 원본은 유지하고 조직+원본 유형+원본 ID로 연결한다.
- 과거 지급완료인데 금액이 없으면 지급액을 추정하지 않는다. 기존 완료 표시와 확인 필요를 함께 유지한다.
- 실제 은행/현금 지급 기록과 지출 배분을 분리한다. 한 지급의 여러 지출 배분, 분할지급, 원지급에 대한 반환, 배분 정정 이력을 지원한다.
- 계약 미설정은 지급 배분 실행만 제한한다. 원본 조회·연결·실제 입출금 기록은 가능하다.
- 은행 원본 ID, 현금 지급 증빙 ID, 조직별 처리키로 중복 등록을 막는다. DB 잠금으로 동시 잔액 초과를 막는다.
- 이전 경로가 통합 연결된 지급액을 직접 덮어쓰거나 원은행 거래를 바꾸지 못하게 DB 트리거로 제한한다. 이 트리거는 원본을 실제로 연결한 뒤 적용된다.
- 같은 조합의 계좌이체를 비용·새 납부·예산 집행으로 생성하지 않는다.
- API에서 사용자/조직을 입력값으로 신뢰하지 않고 기존 Auth 검증과 구성원 조회를 재사용한다. DB 명령도 권한을 재검사한다. 신규 테이블은 서비스 경로 전용 정책과 권한을 적용한다.

## 검증

- `node node_modules/vitest/vitest.mjs run src/features/finance/fund-workflow-domain.test.ts src/features/finance/fund-workflow-repository.test.ts src/features/finance/reimbursement-auth.test.ts`: 3개 파일, 31개 테스트 통과.
- 변경 TypeScript 파일·테스트·격리 검증 스크립트 ESLint 통과.
- `node node_modules/next/dist/bin/next build`: 프로덕션 빌드 통과. 빌드 시점 작업 폴더에는 미커밋 화면 초안도 포함되어 있으므로 화면 완료 증거로 사용하지 않는다.
- 별도 `tsc --noEmit`은 기존 테스트 파일의 타입 오류 14건으로 실패. 변경 전 `3071f40`의 별도 checkout에서도 동일 14건 재현. 신규 기반 파일 오류는 없음. 이 검사는 통과로 보고하지 않는다.
- `node scripts/test-finance-workflow.mjs`: 최종 코드에서 통과. 운영 자격증명 없이 새 Docker PostgreSQL을 만들고 전체 로컬 스키마/마이그레이션을 적용한다. 개인 정산, 통합 예산, 부분 예약 기존 SQL 테스트와 새 지급 SQL 테스트, 별도 세션 동시 배분/동일 처리키 재시도, 실제 DB 역할 접근거절을 검증한다. 현금 중복, 다른 조직 계좌, 다른 계약의 승인 재사용, 미래 지급/이체, 사용 전 환급/지급 전 회수도 거절되는지 확인했다. 실행 후 해당 스크립트 소유 컨테이너만 정리한다.
- 화면 저장·새로고침, 메뉴/활성/모바일, 신탁 양식/첨부, 운영 배포는 아직 검증하지 않았다.

## 다음 단계

계약 버전과 적용 근거를 설정하는 서버 명령, 기존 지출을 선택하는 신탁 요청, 항목별 심사/보완/부분승인, 제출 스냅샷과 첨부 버전, 철회 확인과 재제출을 구현한다. 계약 자료가 없는 항목은 설정 필요로 유지하되 초안·조회는 제공한다. 운영비 선교부·기간잠금·자동 계정분개는 근거 없는 기본 정책으로 활성화하지 않는다.
