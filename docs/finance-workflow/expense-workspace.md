# 4a 공통 지출 원본 화면

`/finance/expenses`는 기존 결의·간편지출·개인 대납 정산을 원본 ID로 조회하는 공통 입구다. 원본을 이전하거나 동일 거래를 새 지출로 복제하지 않는다.

## 구현 범위

- `finance.expense_workspace`는 검증된 조직의 원본을 JSON으로 반환한다. 최근 100건으로 제한하지 않는다. 직원은 조직 전체, 일반 신청자는 본인 PERSONAL만 조회한다.
- 원본 종류·통합 연결·제목/문서번호/거래처 검색과 정확한 원본 건수를 제공한다. 같은 사용을 전환한 원본이 여럿일 수 있으므로 금액 총합은 제공하지 않는다.
- `?source_kind=RESOLUTION|QUICK|PERSONAL&source_id=...`는 새 공통 화면 자체의 상세 선택이다. 기존 결의 화면에 존재하지 않는 ID 상세 기능을 가정하지 않는다.
- `?kind=...&connection=ALL|CONNECTED|UNCONNECTED&q=...`는 목록 필터다. 다른 query 문맥은 보존한다.
- 상세는 원본 날짜/상태, 연결된 지급 잔액, 해당 지출의 신탁 항목, 발생·지급 회계전표 연결을 표시한다. 전체 계좌번호·증빙 저장 경로·다른 신청자의 원본은 반환하지 않는다.
- 연결은 기존 `workflow_command ENROLL`을 재사용한다. 동일 종류+원본 ID 유일 제약과 처리키 재시도로 중복을 막고, 연결 후 재조회한다. 원본의 지급완료 상태를 초기화하지 않는다.
- 신탁 이동은 `?request=...`, 회계 이동은 `?voucherId=...`를 사용한다. 지급 이동은 제목 검색 목록임을 표시한다.

## 등록 시작과 기존 기능 재사용

| 선택 | 현재 연결 |
| --- | --- |
| 앞으로 지급할 거래 | 기존 `/finance/expense-resolutions` 작성·관리. 기안 생략과 결의 승인 생략을 구분해서 안내 |
| 이미 사용하거나 지급한 거래 | 개인 대납은 `/finance/reimbursements`, 결의 생략 근거가 있는 경우 `/finance/quick-expenses`, 사후 결의는 기존 결의 작성·관리 |
| 먼저 지급한 돈의 정산 | 통합 선지급 정산은 미완료로 명시. 현재 지급·결의 자료 확인 링크 제공 |

기존 작성·승인·출력 화면은 유지한다. 공통 화면의 링크는 각 기존 목록으로 이동하므로 문서번호/제목으로 찾아야 한다. 일반 신청자에게 직원용 작성·지급·회계 링크를 제공하지 않는다.

## 검증과 미완료 범위

SQL 검증은 105개 원본의 전체 조회, 조직·개인 권한, 비공개 필드 배제, ENROLL 저장·재조회·중복 처리, 원본 지문 보존, 신탁·회계 링크를 검사한다. UI 검증은 필터/건수/선택 상세, 실제 기존 경로, 실패 후 같은 키 재시도, 이중 클릭 차단, 저장 후 재조회, 일반 사용자 메뉴를 검사한다.

이 단계는 공통 조회·상세·등록 입구를 구현한다. 다음 항목은 별도 단계이며 이 문서로 완료 처리하지 않는다.

- 선지급 원지급·사용액·잔액 반납·추가 지급의 통합 정산
- 공통 화면에서 모든 작성·결재 기능을 직접 실행하는 통합 편집기
- 전체 사이드바 및 업무현황 개편
- 운영 DB 마이그레이션, 실제 배포, 운영 화면 검증

테스트 실행 결과와 운영 적용 여부는 전체 구현 보고서에 별도로 기록한다.
