# 담당자 선지급 정산 초안 구현

2026-09-08. 운영 적용 전 로컬 검증 단위. 설계 기준: `advance-settlement-design.md`.

## 구현 범위

- `/finance/advance-settlements`: 실제 원지급 선택, 각 지급 배분을 최초/추가로 명시 분류, 기존 사용 원본 및 증빙 참조, 초안 저장·재조회·상세.
- `advance_settlement_source`: ADVANCE + EMPLOYEE_ADVANCE 원본의 실제 OUT/DISBURSEMENT 배분만 후보. 승인액·과거 지급완료 상태·작성일로 실제 지급을 만들지 않는다.
- 반환은 선택 원배분의 실제 IN/RETURN 배분만 한 번 반영하고 역분개 배분은 제외한다. 추가 지급은 같은 원본 거래의 실제 배분만 연결한다.
- 사용 원본은 RESOLUTION/QUICK/PERSONAL 고유 ID 및 기존 명시적 연결 ID로 예약한다. 같은 증빙 파일 내용 해시의 중복 연결도 거절한다. 제목·사람 이름으로 동일성을 판단하지 않는다.
- ADMIN/APPROVE는 초안을 저장하고 ADMIN/APPROVE/PAY/CLOSE/SENIOR는 조회한다. 일반 신청자 이름을 담당자 이름에 매칭하지 않는다.
- 조직 잠금, 예상 버전, 원지급/사용 스냅샷 서명, 동일 처리키 재시도, 원본별 고유 제약, 감사 이벤트를 적용한다. 저장 실패 시 초안/예약은 원자적으로 롤백한다.
- 과거 지급액 대조 필요, 별도 지급·카드·개인 환급 사용 원본, 증빙 미연결, 원본 변경은 검토 대상으로 유지한다. 예상 검증 예외만 후보에서 제외하고 예상 밖 DB 오류는 조회 실패로 전파한다.
- 기존 원본·실제 지급·예산 집행·전표에는 초안 저장이 영향을 주지 않는다. 파일 경로와 계좌번호는 workspace에 제공하지 않는다.

## 금액 확인 예제

| 실제 최초 지급 | 실제 추가 지급 | 실제 반납 | 초안 사용액 | 초안 차액 |
|---:|---:|---:|---:|---:|
| 1,000 | 0 | 0 | 800 | 200 |
| 1,000 | 0 | 200 | 800 | 0 |
| 1,000 | 0 | 200 | 1,200 | -400 |
| 1,000 | 400 | 200 | 1,200 | 0 |

차액 = 최초 + 추가 − 반납 − 초안 사용액. 차액 0은 정산 완료를 뜻하지 않는다. 원본 사용액이 변경돼도 저장된 초안 금액은 사용자가 재검토 후 저장할 때까지 유지한다. 원지급을 더 이상 검증할 수 없으면 차액은 확인 필요로 표시한다.

## 검증 기준과 남은 범위

`advance_settlement_drafts.sql`은 저장/재조회, 원본 보존, 역할·조직, 버전·서명, 처리키, 사용/증빙 중복, 반납/추가/역분개 산식, 잘못된 파일, 정책 잠금을 검증한다. runner의 실제 두 세션은 다른 원지급에서 같은 사용 원본을 동시에 예약할 때 한 건만 저장되고 실패 초안은 남지 않는지 검증한다. UI/저장소/action focused 테스트는 원본 ID 전달, 실패 입력 보존, 재시도 키, 중복 클릭, 배경 변경, readonly, 금액 구분, 조회 오류를 다룬다.

정산 확정·완료, 승인 규칙, 예산 귀속, 회계 인식, 추가 지급 실행은 정책 미확정으로 미구현/잠금 상태다. 원본별 여러 정산 회차, 별도 결의로 지급된 추가금 연결, 일반 신청자의 선지급 소유권, 과거 미연결 지급금 대사는 후속 범위다. 증빙은 기존 통합 업무에 등록된 EVIDENCE 파일 선택을 재사용하며 이 화면의 신규 업로드는 포함하지 않는다. 운영 DB migration 적용 및 운영 배포는 이 문서 작성 시 수행하지 않았다.
